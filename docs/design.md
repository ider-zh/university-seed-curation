# 初始化设计 · 2026-11-05

状态：根据本次澄清形成的设计草案。离线核心可先验收；公开 seed 导入、
Agent 执行器、生产队列和 GitHub 自动合并需要各自配置并验证后启用。

## 已确定的边界

| 决策 | 约定 |
| --- | --- |
| 对象 | 全球现存和历史高等院校；机构、系统、校区、院系等分别识别 |
| 初始化 | 39,489 条主候选；64,667 条旧规则独有对象保留为补漏任务，不直接冒充已确认高校 |
| Research | 先核验机构身份与名单资格，再按领取的字段任务更新资料 |
| 来源 | 在线 Wikidata 与 Wikipedia 为主，可在其他环境运行；其他网站辅助，批量源通过独立 adapter 接入 |
| 并发 | 一个 Research 主 Agent + 多个 Research subagent + 一个 Review Agent；每个子任务一个 QID，总计三个模型调用额度 |
| Review | 独立会话，对每条变更事实回到来源核验；身份、前后身、分校和对象归属重点检查 |
| 迭代 | 最多两轮修订；仍不一致就标为未决，保留证据，不无限重试 |
| 协作 | 各自工作区；一小批学校一个 GitHub PR，各校独立结论 |
| 公开边界 | 候选、原文和完整 review 过程先私有；PR 只包含通过的学校结果和精简凭据 |
| 应用 | Review 通过后脚本应用；人工负责 Schema 大改与正式数据发布 |
| 自动导入 | 来源规则、Schema、QID 映射均确定时可自动处理；冲突、模糊匹配、异常转 Agent |
| 文件 | 每个 QID 一个 JSON，按 QID 的 SHA-256 前三个十六进制字符分桶 |
| 缺失 | 业务字段省略，不写 null 或空字符串；采集覆盖状态单独记录 |
| 刷新时间 | `update_datetime` 仅在完整 Research＋Review 刷新通过时写入；批处理另记 `modified_datetime` |
| 默认任务 | 优先从未刷新，再选六个日历月未刷新的学校；游标绑定固定任务快照 |

## 系统分层

1. **数据层**：Git 中的单校 JSON、受控 Schema、字段注册表、来源 adapter 规则。
2. **私有工作层**：任务、租约、候选 diff、原始来源缓存、研究/核验尝试及运行日志。
3. **Agent 层**：Research 提交提案，Review 独立判断；均调用同一 skill 的脚本接口。
4. **可信脚本层**：领取与续租、Schema/业务校验、审核结论绑定、CAS 更新、批次组装。
5. **GitHub 层**：已通过记录的小批 PR，CI 复验，受保护 main；正式发布另有人工验收清单。

本阶段采用一个逻辑控制器：Research 主 Agent 管理工作清单和 subagent，单个
Review Agent 消费候选。它们使用共享的私有状态目录及 SQLite 队列；不同 Git
worktree 必须显式指向同一个状态目录。先不要求独立协调服务器或公共 Web 服务。
若以后跨机器执行，配置经 SSH 访问同一个私有协调目录的 transport，不能把
SQLite 放到不支持其锁语义的网络共享盘，也不能给每个工作区复制一份领取状态。
GitHub 管理已审核结果和代码协作，不承担数万条 Issue 的任务数据库。

## 一次完整交付

1. 从被接受的 seed 快照生成私有初始化工作包，校验计数、来源 manifest 和重复 QID。
2. 对主候选创建身份任务；补漏对象只创建补漏任务。初始 screening 与研究结论分别存储。
3. 协调器分发 QID 与字段范围、当前记录版本、来源入口和预算。
4. Research subagent 读取必要上下文、检索来源，提交最小事实 diff；不重写整所学校。
5. 脚本先校验提案结构、字段注册、来源引用、对象归属和当前基线。
6. Review 在新会话里重新读取来源及具体改动，输出逐项结论。
7. 退回学校保留失败记录并修订；通过学校由脚本生成 JSON 与简短审核凭据。
8. 以小批通过学校组装 PR；默认建议每批 5 所，可配置。未决学校不阻塞其他学校。
9. CI 检查可信 Schema、签名/审核凭据、记录基线和允许修改的路径。
10. 合并前重新比对 main。不同学校可重放；同一学校基线已变化则重新组装并复核受影响事实。

## 不同状态不能混为一谈

- seed 中的 `included` 只是初筛支持，不等于研究、逐条 Review 或人工发布验收通过。
- 一个字段未采集，不等于该字段不存在；`0` 和 `false` 不是缺失。
- PR 通过，不等于已正式发布一个数据集版本。
- 不确定的对象、原始声明冲突和模型未达成一致均可交付明确状态；不强造单一答案。
- 新增字段属于数据合同变化。Agent 可以建议，不能通过一个普通学校更新顺手改 Schema。

## 刷新时间与游标

`update_datetime` 表示最后一次完整刷新通过 Review 的时间，使用带时区 ISO 8601
（存储建议 UTC）。首次创建时省略；来源 dump 修改时间不复制成这个字段。
字段补充、外部批处理、格式整理只更新 `modified_datetime`，不重置整校刷新周期。
完整复查后“没有新事实”也可更新刷新时间，但必须确实完成当前 `core-v1` 的所有
字段组核验；部分字段核验不能假装整校已刷新。身份未解决时不能完成整校刷新。

队列创建时固定输入 Git base、`as_of`、六个日历月前的截止时点、候选 QID 和基线。
以 2026-11-05 为例，截止日为 2026-05-05；月末采用日历月末钳位，不等于 180 天。
先排缺少 update_datetime 的学校，再按最早刷新时间及数值 QID 排序。
游标只分页这个固定清单；更新文件不会让后续页漏项。新学校和其他新过期对象在
下一次创建清单时出现。浏览不是领取，只有事务领取才分配 QID。

Research 与 Review 共用三个活跃租约；Review 同时最多一个。它有待办时保留一个
额度，典型运行是两个 Research + 一个 Review，没有 Review 待办时可三个 Research。
任务租约超时会重领，旧 token 不再允许提交。执行器必须续租，失去租约时终止旧
模型调用；跨机器失联后的实际进程回收需要生产 rollout 验证。
最多两轮修订后标记未决，私有队列默认冷却七天，不伪造 update_datetime。
