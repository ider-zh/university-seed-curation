# 初始化验收与实施顺序

1. 完成本次边界澄清，检查数据合同、两个 Agent 角色与批处理规则。
2. 验收离线脚本：路径、缺失值、结构与引用校验、初始创建、任务租约、基线更新。
3. 在私有位置 dry-run 真实 seed；确认导入/去重/分桶数量，不公开未验收的 seed。
4. 配置私有协调位置、访问方式、缓存与 Provider；小样本验证实际三调用并发上限。
5. 用 10 所分层学校验证身份任务：历史、分校、系统、无 Wikipedia、多语言和身份冲突。
6. 人工检查经过独立 Review 的 10 所样本与失败记录，确认身份字段与审核策略。
7. 配置 GitHub required checks、reviewer 验证密钥、可信 CI、自动合并与分支保护。
8. 扩到普通字段任务，再逐个接入已明确的数据源 adapter；正式数据版本单独验收。

本次初始化设计不等于已完成第 3–8 步。不得把离线队列测试、模拟 Review 或仅能
创建 JSON 的脚本描述为已经运行的 Research/Review 多 Agent 工作流。
